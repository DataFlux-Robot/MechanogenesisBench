# 状态与路线图

[English](STATUS_AND_ROADMAP.md) | **简体中文**

快照日期：2026-08-28

## 当前成熟度

MechanogenesisBench 是开发预览版，不是完整 benchmark。当前公开切片可以验证任务包、
运行外部进程、验证内容寻址的多代提交、执行可信评测器并输出向量评分；同时包含小型 Lean
协议内核和负向测试。

当前版本还不足以对第三方系统进行公平排名：任务多样性较窄，物理试验尚未被打包成可复现的
公开套件，评测器只有进程级隔离，而且参考提交是固定的一致性 fixture，而不是学习型智能体。

## 已吸收的近期开发经验

1. **形式可靠性不等于算法可达性。** checker 可以证明被接受的制品满足某个谓词，但不能
   证明智能体有能力生成该制品。benchmark 将把有效性、可达性/执行和经验性能分别报告。
2. **Receipt 不等于它描述的事件。** 未来硬件赛道必须将传感器观测、校准、保管链、构造
   和评测绑定到可独立重放的证据。
3. **环境故障是一等结果。** 依赖故障、OOM、超时、解析失败、构造失败、实验失败必须与
   科学性拒绝区分。
4. **一个可行样本不代表鲁棒性。** 在晋级为 benchmark 声明前，需要任务族宽度、新种子、
   扰动和 held-out 组合。
5. **协议示例不能充当竞争 baseline。** 当前参考系统只检查 ABI 和验证器。

## 开发计划

### M0 — 仓库与治理边界

- 维护干净、只含 benchmark 的公开仓库；
- 发布 schema 版本、弃用和披露政策；
- 在稳定版前选择明确的开源/数据许可证；
- 增加贡献、安全和评测器披露指南。

退出条件：干净 clone 不包含 FLUXPRSI 实现、内部训练轨迹、凭据或无界本地 artifact。

### M1 — 第三方智能体协议

- 冻结首个版本化 MRS/提交 ABI；
- 增加容器化系统 adapter 和确定性资源核算；
- 规定网络、文件系统、重试和人工干预策略；
- 发布至少一个不共享评测器实现、且不是固定脚本的公开 baseline。

退出条件：两个独立实现的智能体无需导入仓库内部代码即可完成同一公开任务。

### M2 — 任务与失败覆盖

- 从当前 fixture 型一致性案例扩展到多种机构、传感、执行、制造和实验设计任务族；
- 增加解析、可行性、构造、计量和因果归因失败套件；
- 注册 held-out 组合 split 与反捷径负控制。

退出条件：任务族和失败阶段覆盖可度量，且单个手写策略无法解决完整套件。

### M3 — 评测器托管与可复现性

- 分离公开任务材料与 sealed 评测资产；
- 增加签名任务/评测器 manifests、确定性重放和篡改检查；
- 用竞赛级隔离方案替换进程级执行；
- 在不泄露 sealed target 的前提下发布参考运行包和复现检查。

退出条件：独立维护者能从不可变包复现每个发布分数和负控制。

### M4 — 物理证据赛道

- 按任务族定义计量、传感器、校准、不确定性和保管链要求；
- 增加仿真器到独立 backend 以及硬件在环资格验证；
- 试点真实构造和实验任务，并明确核算人工与物料。

退出条件：至少一个任务具有可重复、独立审计的硬件证据；仿真与一致性结果保持显式低等级。

### M5 — 有界递归赛道

- 强制跨代的精确 operator 与 checkpoint 谱系；
- posterior selection 声称的每个候选都必须在冻结、匹配的 sibling 协议下执行；
- 区分更新有效性、权重级影响、未来任务贡献和物理贡献；
- 增加针对预置资源、软件补贴、评测泄漏、权重不变和不可达接受状态的负控制。

退出条件：只有当每条边同时具备可执行证据和必要因果/物理资格时，才输出有限递归声明。

### M6 — 公开 benchmark 发布

- 与多个组织和异构智能体开展外部 beta；
- 冻结任务/评测器版本并发布 benchmark cards；
- 建立 issue 分流、结果撤销和排行榜治理机制。

退出条件：只有通过外部复现和威胁模型审查后才发布稳定版。在此之前，仓库结果只是开发证据，
不是对智能体能力的通用排名。
